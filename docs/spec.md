## 一、整體架構

沿用稽核系統（`~/mala-audit`）已驗證過的三層，不引入新技術：

```
手機瀏覽器（加到主畫面後像 App）
   │  純靜態頁，無框架、無 build step
   ▼
GitHub Pages  eason0728.github.io/mala-cashbook
   │  fetch → text/plain（規避 CORS preflight，同稽核系統）
   ▼
Apps Script Web App（doGet / doPost）
   │
   ├── Google 試算表「現金收支明細」── 四個分頁
   └── Google Drive 資料夾 ──────── 收據照片
```

**MODE 切換**（照抄稽核系統慣例）：`js/config.js` 內 `MODE: 'local' | 'cloud'`，
網址加 `?mode=local` 可暫時切成假資料模式。本機測試與自動化測試一律跑 `?mode=local`，
不會碰到真試算表，也因此測試不需要知道正式通行碼。

## 二、資料存放：Google 試算表四個分頁

### 分頁 1「明細」——一列一筆，就是匯出的來源

| 欄 | 名稱 | 說明 |
|---|---|---|
| A | 單號 | `2026-09-001`，年月＋三位流水，後端產生 |
| B | 店別 | 固定 `新竹光復`（保留欄位，未來加店用） |
| C | 日期 | `yyyy-mm-dd`，帳務發生日（可回填前幾天） |
| D | 收支別 | `支出` / `收入` |
| E | 科目 | 讀「設定」分頁的科目清單 |
| F | 項目名稱 | 自由填，例：`示範食品行—冷藏` |
| G | 金額 | 整數，實際付出／收到的錢 |
| H | 發票 | `有` / `無` |
| I | 未稅價 | 後端算：有發票＝`round(金額/1.05)`，無＝金額 |
| J | 稅額 | 後端算：金額 − 未稅價；無發票＝0 |
| K | 收據編號 | 每月各自從 1 起算的流水（跟紙本的 1～28 對得上） |
| L | 照片連結 | Drive 檔案 URL，沒拍照留空 |
| M | 填表人 | 目前固定 `店長`（通行碼只有一組，保留欄位） |
| N | 登記時間 | ISO timestamp，實際按下送出的時刻 |
| O | 狀態 | `正常` / `作廢` |
| P | 作廢時間 | 作廢才有值 |
| Q | 作廢原因 | 選填 |

**沒有實體刪除。** 送出後的任何一筆都只會被標成 `作廢`，列永遠留在試算表裡（2026-09-08 Eason 指示）。
作廢的筆不列入合計、不出現在匯出檔，但在當月清單上仍看得到（灰底、劃線）。

### 分頁 2「設定」

| 鍵 | 值 | 說明 |
|---|---|---|
| `通行碼` | （只存這裡，不進程式碼、不進 GitHub） | 改這格立刻生效，舊碼失效 |
| `店別` | `新竹光復` | 逗號分隔，未來加店改這格 |
| `支出科目` | `食材,蔬果,瓦斯,備品耗材,清潔用品,修繕維護,水電,房租管理費,運費,文具印刷,員工餐費,雜支` | 順序＝下拉順序 |
| `收入科目` | `回收收入,員工／同業購買,代收轉付,其他收入` | 同上 |
| `照片資料夾ID` | Drive folder id | 收據照片存這裡 |

科目清單**不寫死在程式**：會計自己改這一格就生效，不用改程式、不用重新部署。

### 分頁 3「常用項目」——記憶功能的資料來源

| 欄 | 名稱 |
|---|---|
| A | 科目 |
| B | 項目名稱 |
| C | 使用次數 |
| D | 最後使用時間 |

每次成功送出就 upsert 一列（次數 +1）。前端載入時整包取回。

**候選清單的規則（2026-09-08 Eason 拍板，不要自行改動）**：固定 **8 個**，一律依
**「最後使用時間」排序，不是使用次數**。理由是店裡換了廠商之後，舊廠商的累積次數還是最高，
用次數排會一直把已經不用的東西推到最前面。

沒打字時顯示最近用過的 8 個；打字後縮成名稱含有那段字的 8 個。點一下同時帶入名稱與科目。

### 分頁 4「月結」

| 欄 | 名稱 |
|---|---|
| A | 月份 `2026-09` |
| B | 狀態 `鎖定` |
| C | 鎖定時間 |

有 `鎖定` 的月份，後端一律拒絕該月的 create／update／void，回 `LOCKED` 錯誤。

## 三、API（Apps Script Web App）

一律 `POST`，`Content-Type: text/plain`（規避 CORS preflight，同稽核系統），body 是 JSON 字串。
每個請求都帶 `pass`（通行碼），後端逐次比對「設定」分頁；不符回 `AUTH_FAIL`。

| action | 送什麼 | 回什麼 |
|---|---|---|
| `bootstrap` | `{pass}` | 科目清單、店別、常用項目、已鎖定月份清單 |
| `list` | `{pass, month}` | 該月全部明細（含作廢的，前端自己灰掉） |
| `create` | `{pass, date, kind, subject, name, amount, hasInvoice, photoBase64?}` | 新增後的完整那一筆（含單號、收據編號、拆好的稅） |
| `void` | `{pass, id, reason?}` | 更新後的那一筆 |
| `update` | `{pass, id, ...欄位}` | 更新後的那一筆 |
| `lock` / `unlock` | `{pass, month}` | 該月狀態 |

**稅額一律由後端算**，前端只是即時預覽。單一真相在後端，避免前端版本不一致算出不同結果。

### 錯誤碼

`AUTH_FAIL`（通行碼錯）、`LOCKED`（該月已結）、`NOT_FOUND`、`BAD_INPUT`、`PHOTO_FAIL`（照片上傳失敗，
但那一筆帳仍會存進去，前端提示「已記錄，照片沒上傳成功」——不能因為照片而讓帳記不成）。

## 四、前端結構

```
index.html          單頁，五個 <section> 互相切換
css/base.css        設計語彙沿用稽核系統
js/config.js        MODE / GAS_URL / 通行碼開關
js/api.js           後端呼叫，含 mock 分支
js/mock-data.js     ?mode=local 的種子資料（含紙本 9 月那 17 筆）
js/busy.js          「送出中＋秒數」的共用機制
js/memory.js        常用項目記憶（後端資料 + localStorage 快取）
js/export.js        產 xlsx（lazy load vendor/xlsx.full.min.js）
js/views/*.js       login / entry / list / export 四個畫面
manifest.json / sw.js     加到手機桌面用
icons/icon-192.png / icon-512.png
```

### 四個畫面

1. **登入**：通行碼一格。過了存 `localStorage`，之後不用再輸入（同稽核系統）。
2. **登記**（主畫面）：日期（預設今天）→ 支出／收入切換 → **項目名稱** → **科目**（由名稱自動帶入）→
   金額 → 有無發票 → 拍照（可選）→ 送出。**上方常駐本月支出／收入／淨額三個數字。**
   **欄位順序是項目名稱在科目上面**（2026-09-08 Eason 指定）：店長看著收據想到的是「示範食品行」而不是「食材」，
   所以記憶的方向是「名稱 → 科目」——打過的名稱自動把科目填好；沒打過的明講「沒有歷史紀錄，請自己選」，
   送出後就記住。名稱只打到一半、還有候選時不跳警告，那只是還沒打完。
3. **當月清單**：最新在上，**一整張卡片內用分隔線分列**（一頁看得到 6～7 筆，不是 3 筆），
   點某一列才展開「修改／作廢」。當月鎖定時不給操作鍵。
4. **匯出**（會計用）：選月份 → 下載 `.xlsx` → 可鎖定該月。

## 五、三項本次追加的規格

### 5-1 刪除一律留痕
沒有任何路徑會真的移除資料列。送出後只有「作廢」一種操作，寫入 `狀態=作廢`＋`作廢時間`。
未送出的表單（還沒進後端）不算資料，「清空重填」只是清畫面上的欄位。

### 5-2 可加到手機桌面（PWA）
- `manifest.json`：`name` 現金收支登記、`short_name` **現金帳**、`display: standalone`、
  `start_url: ./?src=pwa`、`theme_color` 白（頁首改白底後跟著白）、`icons` 192／512 PNG，
  圖示是品牌紅底＋去背的品牌圖徽。
- **品牌 logo**：正本在 `~/Desktop/麻的小辛辣/總部/品牌資料/麻的小辛 --- 辣 ! -02.jpg`（3000×3000 直式）。
  `assets/` 裡三個去背 PNG 都是從它產的：`logo-full`（完整、登入頁用）、`logo-mark`（圖形、頁首用）、
  `logo-horizontal`（橫式，備用）。頁首刻意用白底——logo 上的字是黑的，壓在紅底上看不清。
- `sw.js`：靜態資源 **network-first**（連不上網路才用快取），API 一律 network-only 不快取。
  刻意不用常見的 cache-first——這是帳本，改版後還在跑舊程式會算錯錢，比慢半秒嚴重得多。
  版本號變動時舊 cache 全清。
- iOS 另外要 `apple-touch-icon`＋`apple-mobile-web-app-capable`＋`apple-mobile-web-app-title`
  （稽核系統就是這樣做的，照抄）。
- 加到主畫面後全螢幕、沒有網址列，開起來跟 App 一樣。

### 5-3 每顆按鈕「送出中＋秒數」
`js/busy.js` 提供 `busy(button, asyncFn)` 包住所有非同步動作（送出、作廢、修改、匯出、鎖定、登入）：

1. 按下 → 按鈕 `disabled`，文字換成 `送出中 0.0 秒`，**每 100ms 更新一次秒數**。
2. 成功 → `已完成 ✓`，停 1.2 秒後復原原本文字。
3. 失敗 → 復原文字，下方紅字顯示錯誤，按鈕可再按。
4. 逾時 20 秒 → 中止並提示「網路太慢，請再試一次」；**不重送**（避免記成兩筆）。

送出期間畫面不鎖死，但同一顆按鈕不能連按——這是防重複記帳的主要手段。

## 六、匯出檔規格

檔名：`現金收支_新竹光復_2026-09.xlsx`，單一工作表 `明細`，第一列標題：

`店別｜日期｜收支別｜科目｜項目名稱｜未稅價｜稅額｜金額｜發票｜收據編號｜收據照片｜填表人｜登記時間`

- 只出 `狀態=正常` 的列，依日期、收據編號排序。
- 支出與收入放同一張表、用「收支別」欄區分，方便直接下樞紐。
- 最後空一列後放三列合計：`支出合計`、`收入合計`、`淨額`。
- 金額欄套千分位數字格式，日期欄套日期格式（不是文字）。
- **產檔方式（2026-09-08 實作時改的決定）**：原本規劃用 SheetJS 在瀏覽器產，實作時改成
  **由後端 Apps Script 用 Google 試算表原生匯出 xlsx**，前端零第三方依賴、也不必下載 900KB 的函式庫。
  本機測試模式（`?mode=local`）沒有後端，就地產 CSV（帶 UTF-8 BOM，Excel 開不會亂碼），檔名標明是測試檔。

## 七、安全

- 通行碼只存試算表「設定」分頁，**不寫進程式碼、不進 GitHub**（同稽核系統）。
- Apps Script 部署為「以我（Eason）的身分執行、任何人皆可存取」——因為前端沒有 Google 登入。
  這代表 Web App URL 等同鑰匙，通行碼是第二道；URL 不對外貼。
- 試算表與 Drive 照片資料夾都不開公開連結；照片 URL 只有登入過的人拿得到。
